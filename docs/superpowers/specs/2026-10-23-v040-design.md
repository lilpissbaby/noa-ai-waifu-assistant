# Waifu Desk 0.4.0 — personajes, voces locales, productividad y avatares VTuber

- Fecha: 23-oct-2026
- Estado: aprobado en conversación (tres partes), una sola release 0.4.0 sin betas
- Base: v0.3.0 (`dbd19d0`)

## 1. Objetivo y alcance

Cuatro bloques en una sola versión:

| Bloque | Qué consigue el usuario |
|---|---|
| A. Personajes y filtros | Varios personajes con su forma de ser, voz y skin; filtros de contenido por tema con niveles; modo +18 con salvaguardas; tarjetas de SillyTavern; Azure OpenAI con políticas de contenido elegidas por petición. |
| B. Voces locales Piper | Voces neuronales locales gratuitas en muchos idiomas: catálogo descargable e importación de packs. |
| C. Productividad | Recordatorios y temporizadores, ver la pantalla, memoria y notas, acciones rápidas con atajo, archivos y documentos, agenda y resumen diario, leer y buscar en la web, avisos de agentes (Paperclip/Hermes). |
| D. Avatares VTuber | Modelos Live2D (los de VTube Studio, Booth, nizima) como skin, con el comportamiento de su `.vtube.json`. |

### Decisiones tomadas con el usuario

- Productividad: las ocho funciones propuestas.
- Proveedor para el chat +18: sin decidir → se deja preparado para todos y documentado.
- Entrega: una sola release `0.4.0`, sin betas.

### Fuera de alcance

- Crear eventos en el calendario (requiere OAuth; se puede hacer con un MCP de Google Calendar).
- Seleccionar texto en otras apps y copiarlo automáticamente (requiere simular teclas con módulos nativos): las acciones rápidas trabajan sobre el portapapeles.
- Modelos Live2D Cubism 2 (`.moc`, `model.json`) y formatos Inochi2D o `.vsfavatar`.
- Visemas a partir del TTS; los labios siguen por amplitud.
- Modelo Live2D de serie (las licencias de los modelos de ejemplo no permiten incluirlos en el repo).

## 2. A. Personajes y filtros

### 2.1 Modelo de datos (config)

```js
personas: [{
  id, name,
  personality,        // forma de ser (texto libre)
  scenario,           // contexto o relación con el usuario (opcional)
  greeting,           // saludo al cambiar a este personaje (opcional)
  examples,           // ejemplos de diálogo (opcional)
  extraInstructions,  // instrucciones extra (opcional)
  skinId,             // skin que se pone al activarlo (null = no cambia)
  voice,              // null = la de Ajustes → Voz; o { mode, systemVoice|voice|piperVoice, speaker, rate }
  filters: { language, violence, politics, romance, sexual },
  avatar,             // imagen de la tarjeta importada (archivo en userData/personas/), opcional
  source,             // { kind: 'template'|'card'|'manual', name? }
}],
activePersonaId,
content: { adultUnlockedAt: null | timestamp },
```

- Migración: si no hay `personas`, se crea una a partir de `assistant.name`, `assistant.personality` y `assistant.extraInstructions` (que dejan de usarse). `assistant.userName` y `assistant.language` siguen siendo globales.
- `assistantName(cfg)` sustituye a `cfg.assistant.name` en todo el código (títulos, confirmaciones, prompt).

### 2.2 Filtros y prompt

| Filtro | Niveles (por defecto en negrita) |
|---|---|
| `language` (lenguaje fuerte) | `avoid` · **`mild`** · `free` |
| `violence` (violencia y temas duros) | `avoid` · **`moderate`** · `free` |
| `politics` (política y religión) | **`neutral`** · `opinions` |
| `romance` (romance y coqueteo) | `off` · **`light`** · `on` |
| `sexual` (contenido sexual) | **`off`** · `suggestive` · `explicit` |

- `buildPersonaPrompt(persona, cfg)` (puro, en inglés) añade al prompt de sistema: personaje, contexto, ejemplos, una instrucción por filtro y los **límites fijos**, que se añaden siempre y ningún ajuste quita:
  - todos los personajes de cualquier contenido romántico o sexual son adultos;
  - nada sexual con menores, personajes descritos o representados como menores o infantiles, ni personas reales identificables;
  - no fomentar autolesiones ni dar ayuda para hacer daño real.
- `sexual: 'suggestive' | 'explicit'` exige `content.adultUnlockedAt`. Sin desbloqueo, el prompt usa `off` aunque el personaje diga otra cosa.
- El desbloqueo +18 es un diálogo en Ajustes → Personajes («Confirmo que soy mayor de edad y que el contenido adulto es legal donde vivo»). Se puede volver a bloquear.
- Aviso visible junto al filtro sexual: «Claude y OpenAI no generan contenido sexual explícito aunque lo actives; depende del proveedor y del modelo».

### 2.3 Plantillas

`profesional`, `alegre`, `tsundere`, `kuudere`, `dulce`, `sarcastica`, `romantica`: texto de personalidad y filtros sugeridos, en los 5 idiomas (`personaTemplates.*` en i18n).

### 2.4 Tarjetas de personaje (SillyTavern)

- `.png` con chunk `tEXt`/`iTXt` `chara` (V2, base64 JSON) o `ccv3` (V3), o `.json`.
- Campos: `name`, `description` + `personality` → `personality`; `scenario`; `first_mes` → `greeting`; `mes_example` → `examples`; `system_prompt` + `post_history_instructions` → `extraInstructions`. `{{char}}`/`{{user}}` se sustituyen por el nombre del personaje y del usuario.
- La imagen de la tarjeta se guarda como `avatar` del personaje; botón «Crear skin 2D con esta imagen» abre el editor 2D con ella.
- Límite: 5 MB por tarjeta; tarjeta sin datos → error claro.

### 2.5 Herramientas para cambiarlo hablando

- `persona_list`, `persona_switch({ name })`.
- `persona_update({ personality?, scenario?, filters? })` sobre el personaje activo:
  - endurecer filtros o cambiar textos: sin confirmación;
  - relajar un filtro: confirmación (diálogo existente de `confirm`);
  - `sexual` ≥ `suggestive` sin desbloqueo: error «el usuario tiene que desbloquear el contenido adulto en Ajustes» y se abre Ajustes → Personajes.

### 2.6 Azure OpenAI

- Preset `azure`: `kind: 'openai'`, `auth: 'api-key'` (cabecera `api-key` en vez de `Authorization: Bearer`), `baseUrl: https://RECURSO.openai.azure.com/openai/v1`, `model` = nombre del despliegue.
- `profile.azurePolicies = { strict, standard, relaxed, unfiltered }` (nombres; vacío = no se usa) y `profile.azurePolicyMode = 'auto' | 'fixed' | 'off'` (+ `azurePolicyFixed`).
- `auto`: nivel según el personaje activo: `relaxed` si `sexual` ≥ `suggestive` o `violence: free`; `strict` si `sexual: off` y `violence: avoid` y `language: avoid`; si no, `standard`. `unfiltered` solo si está definido y `sexual: explicit`. Se envía `x-policy-id: <nombre>`.
- Errores de filtro: HTTP 400 con `code: content_filter` o `finish_reason: content_filter` → mensaje «Azure ha bloqueado la respuesta por su filtro de contenido (categoría: …)» con las categorías de `content_filter_result`.
- `docs/azure/content-filters/main.tf`: `azurerm_cognitive_account_rai_policy` × 3 (`waifudesk-strict` Low, `waifudesk-standard` Medium, `waifudesk-relaxed` High; Prompt y Completion; Hate, Sexual, Violence, SelfHarm) y la política sin filtros comentada con la nota de aprobación de Microsoft. README de la carpeta con los pasos.

## 3. B. Voces locales Piper

### 3.1 Motor

- Fonemizador: `@diffusionstudio/piper-wasm@1.0.0` (`piper_phonemize.js`/`.wasm`/`.data`, espeak-ng, GPL). No se empaqueta: se descarga el tarball de npm (`registry.npmjs.org`), se comprueba con el `integrity` (sha512) fijado en el código y se extraen los tres archivos a `userData/runtime/piper/`.
- Inferencia: `onnxruntime-web` (ya empaquetado) en un **Web Worker de módulo** de la ventana del avatar (`src/renderer/avatar/piper-worker.js`). El fonemizador se carga como Blob ES (`texto + export default createPiperPhonemize`).
- Flujo: texto → `piper_phonemize` (`-l <espeak.voice>`, `--input` JSON) → `phoneme_ids` → sesión ONNX (`input`, `input_lengths`, `scales` = [noise, length/rate, noise_w], `sid`) → PCM float32 → WAV.
- Integración: modo TTS `piper`. `main` envía `tts:piper { id, text, voice }`; la cola del avatar sintetiza al encolar (canalizado: la siguiente frase se prepara mientras suena la actual) y la reproduce como `audio` (lip-sync por amplitud).

### 3.2 Voces

- Carpeta `userData/voices/<key>/` con `model.onnx`, `model.onnx.json`, `MODEL_CARD` (si hay) y `voice.json` (`{ key, name, language, quality, speakers, license, source }`).
- Catálogo: `https://huggingface.co/rhasspy/piper-voices/resolve/main/voices.json` (caché 1 día). Descarga de `.onnx` y `.onnx.json` con progreso y comprobación `md5` del catálogo; `MODEL_CARD` para la licencia.
- Importar: `.onnx` + `.onnx.json` (el `.json` junto al `.onnx` o elegido aparte) o `.zip` con una o varias voces (`fflate`). Límite 300 MB por voz.
- Ajustes → Voz: modo «Voces locales (Piper)», lista de instaladas (probar, borrar, licencia), catálogo filtrado por idioma de la respuesta, importar, hablante y velocidad. En Windows, botón «Instalar más voces del sistema» (`ms-settings:speech`).
- La voz de un personaje puede ser Piper.

## 4. C. Productividad

Todo vive en módulos de `src/main/productivity/` y herramientas en `src/main/tools/`. Un canal común `announce({ text, kind, speak })` (en `src/main/bus.js`, lo implementa `main.js`) muestra el bocadillo, añade un aviso al chat, lanza la notificación y habla según `productivity.notify = 'speak' | 'notify' | 'silent'`.

### 4.1 Recordatorios y temporizadores

- `userData/reminders.json`: `[{ id, text, due, repeat, created }]`, `repeat ∈ null | 'daily' | 'weekdays' | 'weekly' | 'monthly'`.
- Programador: un único `setTimeout` al más próximo (troceado si > 24 días). Al vencer: `announce`, y si repite se calcula la siguiente fecha (`nextDue`, puro, respetando la zona horaria local y los cambios de hora).
- Al arrancar: los vencidos hace menos de 24 h se anuncian como «con retraso»; los más antiguos se descartan (los repetitivos se reprograman).
- Herramientas: `reminder_create({ text, at?, in_minutes?, repeat? })`, `reminder_list`, `reminder_cancel({ id })`. La hora `at` se interpreta en la zona local; el prompt ya lleva la fecha y la zona.
- Ajustes → Productividad: lista con borrar.

### 4.2 Ver la pantalla

- Herramienta `screen_capture({ target: 'screen' | 'window' })`: `desktopCapturer` con la pantalla del cursor o la ventana activa; ventanas del avatar y del chat ocultas (`setOpacity(0)`) durante la captura; JPEG 85 % reducido a 1568 px de lado mayor.
- Confirmación por defecto (`allowAlways` posible). Atajo global «Mira esto» (por defecto `Ctrl+Alt+S`): captura y abre el chat con la imagen adjunta.
- La imagen vuelve al modelo como imagen (ver §4.9). Perfil sin visión (`profile.vision === false`) → la herramienta no aparece.

### 4.3 Memoria y notas

- `userData/memory.json`: `[{ id, text, created }]`. Herramientas `memory_save({ fact })`, `memory_forget({ id })`, `memory_list`. Se inyecta en el prompt («Things you know about the user»), lo más reciente primero, hasta 2000 caracteres. Interruptor y lista en Ajustes.
- Notas: carpeta `productivity.notesDir` (por defecto `userData/notes`). Herramientas `note_create({ title, content })`, `note_append({ title, content })`, `note_search({ query })`, `note_read({ title })`. Archivos `.md`; títulos saneados; nunca fuera de la carpeta.

### 4.4 Acciones rápidas

- Atajo global (por defecto `Ctrl+Alt+Q`): lee el texto del portapapeles y muestra un menú nativo junto al cursor con las acciones.
- Acciones por defecto: traducir (al idioma de las respuestas), resumir, corregir, explicar, responder. Editables y ampliables en Ajustes: `{ id, name, prompt, copyResult }`, con `{text}` en el prompt.
- Ejecución: abre el chat y envía el mensaje compuesto; al terminar, si `copyResult`, copia la respuesta al portapapeles y avisa en el bocadillo.

### 4.5 Archivos y documentos

- Chat: arrastrar o pegar archivos. Imágenes → adjunto de imagen. `.txt .md .csv .json .log` y código → texto. `.pdf` → texto (`pdfjs-dist`, en `main`). `.docx` → texto (`word/document.xml` con `fflate`). Límite 20 MB por archivo y 100 000 caracteres de texto (se trunca con aviso).
- Carpetas autorizadas (`productivity.folders`). Herramientas `files_list({ path })`, `files_search({ query, path? })` (por nombre y por contenido en texto, máx. 50 resultados), `files_read({ path })` (texto, PDF, docx), `files_write({ path, content })` con confirmación. Toda ruta pasa por `resolveInside(roots, path)` (resuelve enlaces simbólicos con `realpath` y rechaza lo que quede fuera).

### 4.6 Agenda y resumen diario

- `productivity.calendars = [{ id, name, url | file }]`. Descarga con caché de 15 min. `ical.js` para eventos, recurrencias y zonas (`VTIMEZONE`; nombres de Windows de Outlook mapeados a IANA con una tabla).
- Herramienta `calendar_events({ from?, to?, query? })`.
- Resumen diario: `productivity.briefing = { enabled, time: 'HH:MM', days: [1..7] }`. A esa hora (o al arrancar si se perdió ese día y aún es antes de las 14:00) se envía al modelo una petición interna («Prepare the user's daily briefing…») con las herramientas disponibles; la respuesta se muestra en el chat y se anuncia.

### 4.7 Web

- `web_fetch({ url })`: `net.fetch`; HTML → `@mozilla/readability` + `linkedom` → texto con título; PDF → texto; máx. 20 000 caracteres y 10 MB.
- `web_search({ query, count? })` si hay buscador: SearXNG (`/search?format=json`), Brave Search API o Tavily (clave cifrada). Resultados: título, URL y fragmento.

### 4.8 Avisos de agentes

- Paperclip: las tareas creadas o comentadas por la app se vigilan (`userData/watch.json`); herramienta `paperclip_watch({ issueId })`. Sondeo cada `productivity.agentPollMin` (2 min) con Paperclip activado. Cambio a `done`, `blocked`, `in_review` o `cancelled` → `announce`. Las cerradas se dejan de vigilar.
- Hermes: `hermes_task({ task, background? })`. En segundo plano devuelve al momento «en marcha» y al terminar añade al chat un mensaje del asistente con el resultado y lo anuncia.

### 4.9 Imágenes en los mensajes

- Mensajes de usuario con `attachments: [{ kind: 'image', file, mime, name } | { kind: 'text', name, text }]`. Las imágenes se guardan en `userData/attachments/` y se cargan al construir la petición; solo las de las tres últimas intervenciones del usuario van como imagen, las anteriores como «[imagen: nombre]».
- Resultado de herramienta con imagen: Anthropic → bloque `image` dentro de `tool_result`; OpenAI-compatible → texto en el mensaje `tool` y un mensaje `user` con la imagen justo después.

## 5. D. Avatares VTuber (Live2D)

### 5.1 Motor

- `pixi.js@8` (`dist/pixi.min.mjs`) y `untitled-pixi-live2d-engine@1.4.0/cubism` (solo Cubism 3/4/5) servidos sin bundler por el import map. Se importan solo con una skin Live2D.
- Cubism Core: `userData/runtime/live2dcubismcore.min.js`. Primera vez: diálogo con el resumen de la licencia de Live2D (propietaria; gratuita para particulares y empresas pequeñas) y enlace a la licencia completa → descarga del SDK oficial (`https://cubism.live2d.com/sdk-web/bin/CubismSdkForWeb-5-r.5.zip`, con `5-r.4` de respaldo) y extracción de `Core/live2dcubismcore.min.js`. Alternativa: importar el `.zip` del SDK o el `.js`. Se carga con `<script>` antes del motor.

### 5.2 Skins Live2D

- `skin.json`: `{ type: 'live2d', files: { model: 'model/<x>.model3.json', thumb }, vts: 'model/<x>.vtube.json' | null, framing: { preset, zoom, offsetY }, expressions: { happy, sad, angry, surprised, relaxed } }`.
- Importar `.zip` o carpeta: se copia todo bajo `skins/<id>/model/` (sin rutas fuera, sin enlaces simbólicos, máx. 300 MB y 2000 archivos). Se busca `*.model3.json`; varios → el usuario elige. `model.json` de Cubism 2 → error claro. Se listan `readme`/`txt`/`pdf` para enseñar sus condiciones.

### 5.3 Comportamiento

- `vts-inputs.js` (puro): señales de `Behaviour` → entradas de seguimiento de VTube Studio: `FaceAngleX/Y/Z`, `FacePositionX/Y/Z`, `EyeOpenLeft/Right`, `EyeLeftX/Y`, `EyeRightX/Y`, `MouthOpen`, `MouthSmile`, `BrowLeftY`, `BrowRightY`, `Brows`, `VoiceVolume`, `VoiceFrequency`.
- Con `.vtube.json`: `ParameterSettings` → para cada uno, entrada → rango de entrada → rango de salida (con `ClampInput`/`ClampOutput`) → suavizado (`Smoothing` 0–100) → `OutputLive2D`. Respiración automática si `UseBreathing`. Expresiones de `Hotkeys` (`ToggleExpression`).
- Sin `.vtube.json`: parámetros estándar (`ParamAngleX/Y/Z`, `ParamBodyAngleX/Y/Z`, `ParamEyeLOpen/ROpen`, `ParamEyeBallX/Y`, `ParamMouthOpenY`, `ParamMouthForm`, `ParamBrowLY/RY`, `ParamBreath`) y los grupos `EyeBlink`/`LipSync` del `model3.json`.
- Emociones → expresiones (`model.expression(...)`), asignadas por nombre (`happy|smile|joy|笑|喜|嬉`, `angry|怒`, `sad|cry|泣|悲`, `surprise|驚`, `relax|calm|照`) o a mano en el editor; vuelta a la neutra al bajar la emoción.
- Animaciones: grupo `Idle` en bucle (del propio motor); saludo → primer grupo `Tap*`/`Greet*`/`Wave*` si existe.
- `Live2DRenderer` cumple la interfaz común (load, layout, apply, render, aspect, headAnchorCss, alphaAtCss, shapeRects, frameInterval, dispose, snapshot): `Application` de pixi sin ticker propio; render manual desde `Stage`; `HitMask` capturada tras cada render.
- Encuadre: `full` / `half` (60 % superior) / `bust` (35 % superior), `zoom` 0,6–1,6, `offsetY` −0,2…0,2.

### 5.4 Editor de modelos

El editor 3D pasa a «Modelos 3D y VTuber»: mismo flujo para VRM y Live2D. Para Live2D: condiciones (archivos de texto del modelo), encuadre sin giro ni cámara, asignación de expresiones, lista de parámetros con deslizadores de prueba.

## 7. Seguridad y privacidad

- Archivos: solo carpetas autorizadas; escritura con confirmación.
- Pantalla: confirmación por defecto; nada se guarda salvo la imagen adjunta al historial (borrable con «Nueva conversación», que borra también sus adjuntos).
- Web: solo `http(s)`, sin redirecciones a `file:`; tamaño limitado.
- Descargas (Piper, Cubism, voces): HTTPS, tamaño limitado y suma comprobada cuando la fuente la publica.
- Importación de `.zip`: rutas normalizadas, sin `..` ni absolutas, límites de tamaño y número de archivos.

## 8. Pruebas

- Unitarias por módulo puro: prompt de personaje y filtros (incluido el bloqueo sin desbloqueo +18 y los límites fijos), tarjetas PNG/JSON V2/V3, política de Azure y errores de filtro, tarball y zip, catálogo Piper, `phoneme_ids`→tensores, `nextDue` (cambio de hora incluido), memoria, notas, `resolveInside`, extracción docx/PDF/HTML, ICS con recurrencias y zonas, SearXNG/Brave/Tavily con servidor simulado, vigilancia de Paperclip, mapeo VTS, búsqueda de `model3.json` y asignación de expresiones, adaptadores con imágenes.
- Smoke (Electron real): pestañas nuevas en 5 idiomas; cambio de personaje con skin y voz; recordatorio de 1 s que llega al chat; captura de pantalla con el servidor simulado; arrastrar un `.txt`; acción rápida; Piper con una voz real (descargada en CI de los releases de GitHub de Piper) que suena y mueve la boca; Live2D con el SDK oficial y un modelo de ejemplo del GitHub de Live2D (en CI; en local, si no hay red, se omite con aviso).

## 9. Riesgos

- URL del SDK de Live2D: puede cambiar con cada versión → lista de URLs de respaldo + importación manual; el CI la comprueba.
- Calidad de Piper según idioma y voz → se muestra la calidad del catálogo y se puede probar antes de elegir.
- Muchos cambios de interfaz en una sola versión → smoke ampliado y capturas en los 5 idiomas.
- Tamaño de la app: dependencias nuevas solo con los archivos necesarios en `build.files`; objetivo < +15 MB.
